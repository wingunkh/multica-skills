# 엑셀 작업 안전 수칙

> 스킬 버전: 1.0.0

## 왜 필요한가
LLM이 엑셀 작업에서 내는 오류는 매번 다른 것이 아니라 **같은 함정 몇 개에서 반복해서 난다.** 수식 대신 값을 박아 넣고, 수식을 써도 계산되지 않은 채 넘기고, 열고 저장하는 것만으로 차트와 매크로를 지운다. 공통점은 **작업자도 모른 채 넘어가고 받는 사람이 나중에 발견한다**는 것이다. 그래서 주의력이 아니라 절차로 막는다.

## 세 가지 원칙
1. **원본은 건드리지 않는다.** 복사본에 작업하고 결과는 새 파일로 낸다.
2. **여는 것은 안전하고 저장이 위험하다.** 파악을 위해 읽는 것은 언제든 해도 된다. 위험한 것은 `save()`다.
3. **계산 결과가 아니라 수식을 쓴다.**

## 작업 절차
모든 작업은 **파악 → 작업 → 검증 → 보고** 순서로 한다. 기존 파일을 다루면서 파악을 건너뛰지 않는다.

## 1. 수식 — 가장 자주 깨지는 영역

**값을 직접 써넣지 않는다.** 합계·평균·건수·비율은 전부 수식으로 쓴다. 파이썬으로 계산한 숫자를 셀에 넣으면 값은 맞아도 **검토와 수정이 불가능한 산출물**이 된다. LLM이 가장 흔하게 저지르는 실수다.

**수식을 쓴 직후 값은 비어 있다. 그게 정상이다.** openpyxl은 수식을 문자열로 쓸 뿐 계산하지 않는다. 이 환경에는 계산 엔진이 없으므로 아래를 지킨다.

- 통합 문서에 `wb.calculation.fullCalcOnLoad = True`를 설정해 **사람이 열 때 자동 계산**되게 한다. 이걸 빠뜨리면 받는 사람이 빈칸을 본다.
- 방금 쓴 수식의 값을 읽으려 하지 않는다. `data_only=True`로 읽으면 전부 `None`이다. 값이 없다고 수식이 틀린 것이 아니다.
- 값을 확인할 수 없으므로 **수식 자체를 검증**한다. 참조 범위에 헤더 행이나 합계 행이 잘못 포함되지 않았는지, 끝 행이 하나 모자라거나 넘치지 않는지 확인한다. 범위가 하나 어긋나도 결과가 우연히 맞아 보일 수 있어 눈으로 못 잡는다.
- 보고할 때 **"수식 오류 여부는 검증하지 못했다"**고 명시한다. 이 환경에서는 보장할 수 없다.

**쓰면 안 되는 함수가 있다.**
- `XLOOKUP`, `XMATCH`, `SORT`, `FILTER`, `UNIQUE`, `SEQUENCE`는 쓰지 않는다. 결과가 여러 셀로 퍼지는 함수인데 openpyxl로 쓰면 좌상단 한 칸만 남는다. 대신 `INDEX`/`MATCH`를 쓰고, 정렬·필터는 파이썬에서 처리한 뒤 값을 쓴다.
- `TEXTJOIN`, `CONCAT`, `IFS`, `SWITCH`, `MAXIFS`, `MINIFS`는 `_xlfn.` 접두사를 붙인다. 안 붙이면 `#NAME?`가 된다. 예: `=_xlfn.TEXTJOIN(",",TRUE,A1:A5)`
- 안전한 쪽은 `SUMIFS`, `COUNTIFS`, `INDEX`, `MATCH`, `IFERROR`, `SUMPRODUCT` 같은 구형 함수다.

**시트 이름에 공백이나 특수문자가 있으면 작은따옴표로 감싼다.** `='점검 결과'!B5` 형태다. 안 감싸면 `#VALUE!`가 된다.

**백분율은 소수로 저장하고 서식으로 표시한다.** 15%는 `0.15`다. `15`를 넣고 백분율 서식을 걸면 1500%가 된다.

**0으로 나눌 수 있는 수식은 `IFERROR`로 감싼다.** 대상 건수가 0인 집계에서 자주 걸린다.

## 2. 파일 손상 — "복구된 레코드" 경고

사람이 파일을 열었을 때 아래와 같은 메시지가 뜨는 경우다.

```
파일 수준 유효성 검사 및 복구가 완료되었습니다.
이 통합 문서의 일부 요소가 복구되거나 삭제되었을 수 있습니다.
제거된 레코드: /xl/worksheets/sheet1.xml 부분의 셀 정보
```

**엑셀은 원인을 알려주지 않는다.** 그래서 원인을 찾기보다 아래를 지켜 만들지 않는 쪽으로 간다.

- **셀에 넣는 문자열이 `=`로 시작하지 않게 한다.** 수식이 아닌데 `=`로 시작하면 엑셀이 수식으로 해석해 깨진 레코드로 처리한다. 값으로 넣어야 하면 앞에 작은따옴표를 붙이거나 다른 문자로 시작하게 한다.
- **수식을 쓸 때 괄호와 따옴표가 맞는지 확인한다.** 잘못된 수식 문자열이 이 오류의 가장 흔한 원인이다.
- **값 타입을 기본형으로 변환한다.** numpy 정수·실수, Decimal, `NaN`, `NaT`를 그대로 넣지 않는다. `int()`, `float()`, `str()`로 바꾸고 결측값은 `None`으로 넣는다. pandas에서 꺼낸 값은 특히 주의한다.
- **제어문자를 제거한다.** 줄바꿈·탭 외의 제어문자가 들어가면 openpyxl이 `IllegalCharacterError`를 내거나 깨진 파일이 나온다. 외부 시스템에서 긁어온 문자열은 정제하고 쓴다.
- **셀 하나에 32,767자를 넘기지 않는다.**
- **색상은 6자리 또는 8자리 16진수로 쓴다.** `"FF0000"` 또는 `"FFFF0000"` 형태다. `"red"` 같은 이름은 쓰지 않는다.
- **사용자 지정 숫자 서식은 검증된 것만 쓴다.** 직접 만들어 넣지 말고 흔한 서식(`#,##0`, `0.0%`, `yyyy-mm-dd`)을 쓴다.
- **병합 범위가 겹치지 않게 한다.** 겹친 병합, 범위를 벗어난 데이터 유효성·조건부 서식 지정도 이 오류를 만든다.

**저장한 뒤 반드시 다시 열어 본다.** 작업이 끝나면 저장한 파일을 openpyxl로 다시 읽어 예외 없이 열리는지 확인한다. 이 한 단계로 손상된 파일을 전달하는 사고 대부분을 막는다.

## 3. 열고 저장하면 사라지는 것

openpyxl은 **자기가 이해하지 못하는 요소를 저장할 때 버린다.** 무엇이 사라졌는지 알려주지 않는다.

사라지는 대상은 차트, 이미지·도형, 피벗 테이블, 일부 조건부 서식과 데이터 유효성, 외부 링크, 매크로다.

- **기존 파일을 다루기 전에 무엇이 들었는지 센다.** 시트 수와 이름, 차트, 이미지·도형, 피벗, 병합 범위, 조건부 서식, 데이터 유효성(드롭다운), 외부 링크, 수식 셀 수, 매크로 포함 여부(`.xlsm`인지), 시트 보호 여부를 기록한다. 읽기만 하는 것이므로 안전하다.
- **위 요소가 하나라도 있으면** 그 파일을 열어 저장하는 방식(라운드트립)을 기본으로 쓰지 않는다. 데이터만 뽑아 **별도 파일**로 결과를 내고 원본 반영은 사람이 하게 하거나, 위험 요소가 없는 **데이터 시트 하나**만 다룬다. 양식 파일처럼 직접 써야만 하는 경우는 아래 작업 유형 C를 따른다.
- **`.xlsm`은 `load_workbook(path, keep_vba=True)`로 연다.** 안 그러면 매크로가 사라진다. 확장자도 `.xlsm` 그대로 저장한다.
- **외부 링크가 있는 파일은 저장하지 않는다.** 다른 파일을 참조하는 수식은 캐시된 값이 유일한 데이터인데, 재저장하면 그 값이 지워지고 `#NAME?`가 되면서 링크가 통째로 삭제된다. 값이 필요하면 먼저 읽어서 따로 보관한다.
- **pandas로 기존 파일을 열어 저장하지 않는다.** 서식·병합·주석·조건부 서식이 전부 사라진다. pandas는 데이터를 읽거나 새 파일을 만들 때만 쓴다.

## 4. 절대 쓰지 않는 조합

- **`data_only=True`로 연 워크북을 저장하지 않는다.** 모든 수식이 값으로 치환되어 영구히 사라진다. 이 옵션은 값을 읽을 때만 쓰고, 그 워크북으로는 저장하지 않는다.
- **원본 파일을 덮어쓰지 않는다.** 결과는 항상 새 파일로 낸다.
- **`read_only=True`, `write_only=True`로 기존 파일을 수정하지 않는다.** 속도를 얻는 대신 서식과 기능이 대량으로 손실된다.
- **시트 복사로 서식을 옮기지 않는다.** 셀과 일부 속성만 복사되고 이미지·차트는 복사되지 않는다.

---

## 5. 기존 파일 편집 예절

**구조를 바꾸지 않는다.** 더 나아 보인다고 열 순서를 바꾸거나 시트를 재구성하지 않는다. 요청받은 것만 한다. 시트명, 헤더, 지정된 수식은 그대로 둔다.

**입력 칸에만 쓴다.** 기존 파일에는 사람이 채우도록 표시해 둔 칸이 있다. 글꼴 색이나 채우기 색으로 구분되는 경우가 많다. 그 칸만 찾아 쓰고 **기존 수식은 건드리지 않는다.**

**병합된 셀은 좌상단 셀에만 쓴다.** 나머지는 읽기 전용이라 쓰려고 하면 예외가 난다.

**새 행의 서식은 바로 위 행에 맞춘다.** 날짜 칸은 날짜 서식, 숫자 칸은 숫자 서식이어야 한다. 날짜를 문자열로 넣으면 정렬과 필터가 깨진다.

---

## 6. 자격증명이 든 파일

패스워드 관리 대장처럼 비밀번호·토큰·키가 들어 있는 파일을 다룰 때는 **값이 파일 밖으로 새지 않게** 한다.

- 해당 열의 **값을 출력하지 않는다.** 확인이 필요하면 셀 위치와 건수로만 다룬다. 실행 로그에 그대로 남는다.
- **보고에 값을 쓰지 않는다.** "3개 행의 비밀번호 열 갱신"처럼 위치와 건수만 쓴다.
- 오류가 나면 **값이 포함된 메시지를 그대로 출력하지 않는다.**
- 작업 후 **임시 사본을 지운다.** 결과 파일을 공유 위치에 두지 않는다.

## 작업 유형별

### A. 기존 관리 대장에 행 추가·수정
자산·계정·라이선스 대장처럼 서식이 잡힌 파일을 갱신하는 작업이다.

- 추가하는 행은 **기존 마지막 데이터 행 바로 다음**에 넣는다. 빈 행을 사이에 두면 표 범위와 필터가 끊긴다.
- 표(테이블) 객체, 조건부 서식, 드롭다운이 있으면 **적용 범위가 새 행까지 늘어났는지** 확인한다. 늘어나지 않았으면 보고에 적는다.
- 수정은 해당 셀만 바꾸고 주변 셀을 다시 쓰지 않는다.
- 열이 부족하면 새 열을 만들지 말고 멈춘 뒤 보고한다.

### B. 집계·통계 표 만들기
점검 결과 집계, 가용률 계산, 월별 통계처럼 숫자를 계산하는 작업이다. **1번 그룹의 함정이 전부 걸린다.**

- 원본 데이터 시트와 집계 시트를 나눈다. 데이터가 바뀌면 집계가 따라가는 구조가 된다.
- 모든 집계는 수식으로 쓰고, 범위·백분율·0 나누기를 1번 그룹 기준으로 점검한다.
- 결과가 상식적인 범위인지 본다. 가용률 1200%, 음수 건수는 수식 오류다.

### C. 기관 제출 양식 채우기
기관이 보낸 양식 파일에 값만 채워 회신하는 작업이다. **양식을 훼손하면 다시 받아야 한다.**

양식 파일에는 로고, 병합 머리글, 드롭다운, 보호 셀이 거의 항상 있다. 그래도 직접 채우되 아래 조건을 전부 지킨다.

- 원본을 따로 보관하고 **복사본에 작업**한다.
- **입력 칸의 값만** 바꾼다. 머리글·안내 문구·행렬 구조·서식을 건드리지 않는다.
- 드롭다운이 있는 칸은 **목록에 있는 값**만 넣는다. 비슷한 표현을 만들지 않는다.
- 지시가 없는 빈칸에 "해당없음", "-"를 임의로 채우지 않는다. 판단이 안 되면 그 칸을 비우고 보고에 적는다.
- 시트 보호를 **해제하지 않는다.** 보호를 풀어야 쓸 수 있는 칸이면 멈추고 보고한다.
- 작업 후 검증에서 **하나라도 줄었으면 결과물을 버린다.** 복사본을 지우고, 무엇이 사라졌는지와 사람이 직접 채워야 한다는 것을 보고한다. 같은 방식으로 다시 시도하지 않는다.

---

## 검증
저장한 뒤 아래를 순서대로 확인한다.

1. **다시 열린다.** 저장한 파일을 openpyxl로 다시 읽어 예외가 나지 않는지 본다.
2. **줄어든 것이 없다.** 기존 파일을 수정했다면 처음 센 항목(시트·차트·이미지·피벗·병합·조건부 서식·드롭다운·수식 셀 수)을 다시 세어 비교한다.
3. **수식 범위가 맞다.** 쓴 수식의 참조 범위를 실제 데이터 범위와 대조한다.
4. **쓴 셀을 확인한다.** 추가·수정한 셀 두세 개의 값과 서식이 의도대로인지 본다.

줄어든 항목이 있으면 **결과물을 버리고 다른 경로를 고른다.** 두 번 시도해도 같은 결과면 멈추고, 무엇이 사라졌는지와 사람이 직접 작업해야 한다는 것을 보고한다. 같은 방법을 반복하지 않는다.

## 보고
- 무엇을 바꿨는지 (시트·행·셀 범위 기준, 자격증명 값은 제외)
- 검증 결과 (다시 열림 / 보존 확인됨 / 줄어든 항목)
- 수식이 있으면 **"파일을 열면 자동 계산됩니다"**와 **"수식 오류 여부는 이 환경에서 검증하지 못했습니다"**
